# 移动端响应式体验优化设计

## 背景

当前前端由 FastAPI + Jinja 模板 + 全局 CSS 组成，主要页面位于 `app/web/templates/`，全局样式位于 `app/web/static/css/style.css`。

代码巡检发现当前移动端体验问题集中在布局基础设施缺失：

1. `style.css` 没有 `@media` 断点。
2. `.sidebar` 固定 260px 且常驻，`.main-content` 固定 `margin-left: 260px`。
3. 多个页面使用横向按钮组、固定 `min-width`、桌面表格和较大的面板 padding。
4. 搜索结果链接行、任务表格、配置表单和弹窗在小屏上容易挤压或横向溢出。

本次采用方案 2：**全局响应式基础 + 高频页面专项收敛**。

## 目标

1. 让所有主要页面在 375px 手机宽度下可正常浏览、操作和保存配置。
2. 建立全局移动端导航、容器、网格、按钮、表单、弹窗和 Toast 的响应式基础。
3. 针对高频页面补充移动端布局规则，避免页面级内联样式撑破屏幕。
4. 保持现有后端接口、业务流程和页面脚本行为不变。

## 非目标

本次不处理以下内容：

1. 不引入 Vue、React 或新的构建链路。
2. 不重写全部页面为移动端专用视图。
3. 不改变 API、表单字段名、保存 payload 或后台任务逻辑。
4. 不新增底部 Tab、离线能力、手势交互或复杂动画。
5. 不处理品牌视觉重设，只做可用性和信息密度优化。

## 设计原则

1. 优先使用全局 CSS 兜底，减少逐页改动。
2. 对页面内联样式无法覆盖的地方，做小范围模板调整。
3. 移动端以可扫描、可点击、不横向溢出为第一优先级。
4. 保留桌面端现有信息架构和视觉风格。
5. 不把页面说明文案变成教程，不增加无关说明。

## 全局布局设计

### 移动端顶部栏

在 `base.html` 中新增移动端顶部栏：

1. 左侧为菜单按钮。
2. 中间显示 `Python-STRM`。
3. 右侧保留主题切换入口或留空，避免顶部拥挤。

桌面端继续使用固定侧栏，移动端顶部栏只在小屏显示。

### 侧栏抽屉

移动端下 `.sidebar` 从常驻侧栏变为抽屉：

1. 默认通过 `transform: translateX(-100%)` 隐藏。
2. 点击菜单按钮后给 `body` 或 `.sidebar` 添加打开状态类。
3. 打开时显示遮罩层，点击遮罩或导航链接关闭。
4. 抽屉宽度使用 `min(82vw, 280px)`，避免占满整个屏幕。

### 主内容区域

移动端下 `.main-content`：

1. 取消 `margin-left`。
2. 使用 `width: 100%` 和较小 padding。
3. 页面标题字号下调。
4. `.content-wrapper`、面板和网格保证 `min-width: 0`。

## 通用组件响应式规则

### 面板

`.glass-panel` 在小屏下：

1. padding 从 `2rem` 收敛到 `1rem`。
2. 圆角保持但不过度占空间。
3. 禁止 hover 位移动画影响触屏体验。

### 网格

`.grid-2`、`.grid-3` 在小屏下统一变为单列。

图库类容器保留独立规则：

1. 资源图鉴在手机上优先双列。
2. 极窄屏或内容过长时降为单列。

### 表单和按钮

移动端下：

1. `.form-control`、`select`、`textarea` 保持 100% 宽。
2. 横向表单行改为纵向堆叠。
3. 按钮默认允许换行，主操作按钮可占满一行。
4. 内联 `min-width: 280px / 300px` 的搜索框、路径框在小屏下改为 `min-width: 0`。

### 表格

桌面表格结构不改。

移动端下：

1. 表格外层保留横向滚动容器。
2. 表格字号和单元格 padding 收敛。
3. 长错误、任务名、路径字段继续省略显示，完整内容保留在 `title` 或可横向查看区域。

### Modal 和 Toast

移动端下：

1. Modal 宽度使用 `calc(100vw - 2rem)`。
2. Modal 最大高度使用 `calc(100dvh - 2rem)`。
3. 底部按钮区允许换行，必要时主按钮占满。
4. Toast 从右下角改为底部居中，宽度不超过视口。

## 重点页面专项设计

### `library.html`

目标：资源图鉴在手机上能快速搜索、导入和浏览海报。

调整：

1. 顶部标题和工具栏在小屏分成多行。
2. 搜索框占满一行，搜索按钮与分页大小、导入按钮自动换行。
3. `libraryContainer` 小屏改为 `repeat(2, minmax(0, 1fr))`，极窄屏降为单列。
4. 卡片内海报保持固定比例，标题和简介不撑破卡片。

### `search.html`

目标：搜索和转存链路在手机上可单手完成。

调整：

1. 搜索输入、来源选择、搜索按钮在手机上纵向排列。
2. 资源过滤项保持换行，并减小间距。
3. 插件高级区按钮自动换行。
4. 搜索结果里的链接行从横向压缩改为纵向布局：类型、链接、提取码、转存按钮分层展示。
5. 转存 Modal 底部按钮在小屏堆叠。

### `tasks.html`

目标：后台任务在手机上可观察，不要求完全无横向滚动。

调整：

1. 总览卡片在手机上保持 2 列或单列。
2. 顶部刷新、自动刷新控件允许换行。
3. 表格容器保留横向滚动，同时收紧列间距、字号和错误信息宽度。
4. 若任务池字段已由接口返回，表格可以作为附加信息展示；本次移动端优化不强制改数据结构。

### `monitor.html`

目标：Tabs 和长表单在手机上不挤压。

调整：

1. Tabs 容器横向可滚动或自动均分，避免标签挤压。
2. 标题行中的按钮和开关在小屏换行。
3. 开关类表单行在手机上使用 `justify-content: space-between` 并允许文本换行。
4. 保存按钮在手机上占满可用宽度。
5. TMDB 配置 Modal 的搜索条件在手机上纵向排列。

### `strm.html`

目标：STRM 配置、扫描源目录和历史弹窗在手机上可读。

调整：

1. 顶部两列设置区在小屏改为单列。
2. 扫描源操作按钮组自动换行，手机上按钮占满或半宽。
3. 扫描源目录列表项在小屏改为纵向展示，删除按钮不挤压目录名。
4. 同步历史表格保留横向滚动。

### `transfer.html`

目标：分类规则和 STRM 覆盖输入在手机上可编辑。

调整：

1. `.category-rule-row` 从三列改为单列。
2. 分类页面标题操作按钮自动换行。
3. `rewriteArchiveRoot` 小屏占满一行。
4. 回滚预览 Modal 按钮区允许换行。

### `115.html`

目标：115 接入配置在手机上不横向溢出。

调整：

1. 顶部三个 select 从横向三列改为纵向。
2. 保存、扫码、检查状态按钮在小屏自动换行，必要时占满一行。
3. 二维码区域居中并限制最大宽度。
4. 用户状态卡片在小屏保持图标和文本可读。

## 测试与验证

### 自动化验证

运行现有 Python 测试：

```bash
PYTHONPATH=. uv run pytest -q
```

预期：不引入后端回归。

### 手工视觉验证

启动本地服务后至少检查：

1. 375px 宽度：`/`、`/library`、`/search`、`/tasks`、`/monitor`、`/strm`、`/transfer`、`/115`
2. 768px 宽度：同上
3. 桌面宽度：确认原有侧栏和桌面布局未明显退化

重点检查：

1. 无全局横向滚动。
2. 侧栏抽屉可打开、关闭、点击导航后关闭。
3. 主操作按钮可点击且文字不溢出。
4. Modal 不超出视口。
5. 表格横向滚动只发生在表格容器内部。

## 风险与控制

1. 页面中存在大量内联样式，全局 CSS 覆盖可能不足。处理方式是只对高频页面做最小模板调整。
2. 移动端导航需要少量 JS。处理方式是放在 `base.html`，保持无依赖、无状态管理。
3. 表格转卡片会扩大范围。处理方式是本次保留表格，仅优化容器与小屏密度。
4. 外部 Font Awesome 和 Google Fonts 网络加载不稳定不在本次范围内。

## 验收标准

1. 375px 宽度下主要页面不被固定侧栏挤压。
2. 页面主体、表单、按钮、弹窗不出现不可操作的横向溢出。
3. 高频页面的主流程可完成：搜索、转存弹窗、资源图鉴搜索、任务刷新、监控配置保存、STRM 同步操作、转存规则保存、115 配置保存。
4. 桌面端侧栏导航和原有页面结构保持可用。
5. 现有测试通过。
